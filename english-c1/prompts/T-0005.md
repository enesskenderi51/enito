# Prompt T-0005: Reading Task 3 und 4 im offiziellen Phrasenformat

**Ticket:** `tickets/T-0005.md`
**Report:** `reports/T-0005.md`

## Rolle
Du hast einen PhD in Computer Science und Mathematik und bist ein Principal Software Architect eines FAANG Unternehmens mit 30 Jahren Softwareentwicklungserfahrung. Deine Stärken liegen in Algorithmen und Datenstrukturen.

## Ziel
Kompletter Reading Test in allen neun Tests im echten Advanced Format, ohne Buchoriginale zu verlieren.

## Kontext
* `readingTexts` mit `{title, text, qs, sec, start}`, Fragen werden über `q.p` (Index in `readingTexts`) dem Text zugeordnet, Lernstand über `qid` (Text der Frage)
* `buildFullReading` gruppiert nach dem Buchstaben im Titel und sortiert nach Task 1 bis 4
* Vorbild: Test I Task 3 und 4

## Arbeitsregeln
Es gelten R1 bis R8 aus `prompts/META_PROMPT.md`. Besonders wichtig: R4 (eine Quelle der Wahrheit: `practice` am Datensatz statt Sonderliste im Code), R6.

## Phase 1: Erkunden
* Wie gruppiert `buildFullReading`, wo werden Indizes `p` vergeben, was hängt am Titel

## Phase 2: Planen
* **Datenmodell**: neues Feld `practice: true` an den alten Task 3 und 4 von A bis H. Neue Tasks werden hinten angehängt, damit alle bestehenden Indizes `p` stabil bleiben. Verworfen: alte Titel ändern (bricht bindendes Titelformat), Sonderliste im Code (zweite Quelle der Wahrheit)
* **Filter** in `buildFullReading`: einmal `examTexts = readingTexts.filter(t => !t.practice)`, danach unverändert. O(n)
* **Inhalt**: 16 Tasks, 88 Lücken, Phrasen mit zwei bis vier Wörtern, plausible Ablenker, deutsche Erklärung, Lösungsposition gemischt

## Phase 3: Umsetzen
1. Tier 1 und Tier 2 Tests zuerst | fertig wenn: rot
2. Filter in `buildFullReading`, Feld `practice` setzen | fertig wenn: Tier 1 grün
3. Inhalte anhängen | fertig wenn: Tier 2 grün
4. Tier 3 | fertig wenn: alle grün

## Phase 4: Verifizieren
* `npm run test:t1`, `npm run test:t2`, `npm run test:t3`
