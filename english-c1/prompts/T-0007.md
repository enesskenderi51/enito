# Prompt T-0007: Writing mit mehreren Tests und Musterantworten

**Ticket:** `tickets/T-0007.md`
**Report:** `reports/T-0007.md`

## Rolle
Du hast einen PhD in Computer Science und Mathematik und bist ein Principal Software Architect eines FAANG Unternehmens mit 30 Jahren Softwareentwicklungserfahrung. Deine Stärken liegen in Algorithmen und Datenstrukturen.

## Ziel
Aus einem fest verdrahteten Writing Test einen datengetriebenen Pool aus mindestens fünf Tests machen, mit geprüften Musterantworten.

## Kontext
* Panel `p-writing`: drei `.wtask` Blöcke mit `.prompt`, Textfeldern `w1a`, `w1b`, `w1c`, `w2`, `w3`, Musterantworten `m1` bis `m3`
* Script: `countWords`, Wortzähler, Timer, `taskDescriptions` (fest), `getTexts` (Namen fest), KI Korrektur über `askClaude`
* Helfer: `ShuffleBag`, `esc`, `fmtClock`

## Arbeitsregeln
Es gelten R1 bis R8 aus `prompts/META_PROMPT.md`. Besonders wichtig: R4 (eine Quelle der Wahrheit: Prompt, Musterantwort und KI Beschreibung kommen aus demselben Datensatz), R6.

## Phase 1: Erkunden
* Welche Stellen hängen am festen Test (HTML Texte, Namen in `getTexts`, `taskDescriptions`, Wortzahlen in Überschriften)

## Phase 2: Planen
* **Daten** `writingTests`: `[{id, title, part1:{members:[{name,msg,model}]}, part2:{sender,email,notes,model,tips}, part3:{site,topic,notes,title,model,tips}}]`, eingefroren
* **Reine Funktionen**: `writingTaskDescription(test, part)` für die KI, `modelWordCount` über `countWords`
* **Zustand**: `currentWritingTest` als einzige Quelle, `renderWritingTest` schreibt Prompts, Namen und Musterantworten. Auswahl über `ShuffleBag` oder Dropdown
* **Prüfregeln Tier 2**: Wortlimits, Kurzformen in Teil 1 Pflicht, in Teil 2 verboten, Teil 3 enthält jede Zahl aus den Notes
* Entwurfsmuster: keines nötig ausser der Trennung Daten, Logik, Darstellung

## Phase 3: Umsetzen
1. Tier 1 und Tier 2 Tests zuerst | fertig wenn: rot
2. Daten und Funktionen, HTML auf Platzhalter umstellen | fertig wenn: Tier 1 grün
3. Inhalte bis Tier 2 grün
4. Tier 3 | fertig wenn: alle grün

## Phase 4: Verifizieren
* `npm run test:t1`, `npm run test:t2`, `npm run test:t3`

## Abschluss
1. Security Audit
2. `/simplify`, danach Tier 1 erneut grün
3. CLAUDE.md aktualisieren
4. Report `reports/T-0007.md`
5. Ticketstatus auf "erledigt"
6. Commit und Push
